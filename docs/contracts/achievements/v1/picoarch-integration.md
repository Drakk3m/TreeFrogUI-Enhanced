# PicoArch implementation plan

1. Add opt-in identity verifier at effective content load, starting with NES raw whole content. Layer exact hashing and full-path stability over core loading; leave incompatible paths playable without RA. Preserve the tag and lab branch.
2. Add provider registry keyed by known installed core ABI, binary digest and console. Start with measured FCEUmm 2 KiB NES system RAM. Implement checked read functions and rcheevos feature gating. Export the runtime-owned capability evidence record and present separate failure states. Do not trust removable-media requests to expand addressability.
3. Read and activate one exact validated v1 definition set through rcheevos. Map achievement IDs to deterministic positive runtime IDs (ASCII sort, one-based). Reuse the post-retro_run evaluation, readiness and clear-on-discontinuity behavior. Bound runtime allocations and event queue. Disable generalized runtime on ambiguity, invalid sets and unsupported providers.
4. Implement two-slot atomic durable local store, crash-recovery and profile latching, with an event-driven flush. Unit-test storage failure transitions and isolate temporary files. Reuse the compositor/audio notification and surface durable vs unsaved status. Validate during normal pause, save/restore, rewind, fast-forward and shutdown without replacing the default core.
5. Prove original NES lab end to end through generalized definitions with the accepted fixture, retain the old POC regression path and compare behavior on a test card. Only then design archive adapters, disc support and other core profiles. Do not claim official synchronization eligibility.

Open questions before target enablement: precise run-to-run capability evidence channel to FrogUI, temporary full-path source immutability on FAT, worker scheduling/flush latency and bounded resources, PicoArch support for core identity at load and deterministic profile selection. These do not alter the serialized identities or host fixture outputs.
