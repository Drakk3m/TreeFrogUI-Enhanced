The companion JSON projects 66 Studio logical records, their declared extensions, both launcher representations, aliases and source-observed core associations. It also reports 22 FrogUI-only routes and Studio inventory-only folders. Unqualified identifiers remain visible for audit but fail closed as executable or RA platform associations. The source generator reads existing maps. Do not maintain another independent Studio platform list. Studio and Enhanced adapt their existing registries to the same verified keys and test the shared projection against changes. Association evidence is not a memory map or core test. Examples of quarantined groupings are FDS, SuperGrafx grouped as PCE, and ambiguous Neo Geo/MAME or Atari family routes. Audit and explicitly qualify each before promoting it into the supported binding.

## Source trace and host evidence

1. Studio Universal Apply staged the original lab at roms/nes/audit.nes, with logical platform FC in the legacy identity, console ID 7, known RA hash and runtime_ready false. The fixture is from actual 88.3.26 Review and Apply, without official definitions. The historical 88.3.23 package was unavailable.
2. FrogUI scans the ROM path and supplies physical folder nes to Details and ra_game_read. The accepted reader rejected FC from this real fixture when called with nes, and accepted it with FC under controlled file stat. Contract resolver now maps both to fc, requires console 7 and leaves exact key and other public metadata checks in place. The reference check preserves the original sanitized export byte-for-byte. It does not run a changed device reader.
3. A standard NES Details launch reaches the existing launch_by_path rule. Host code extracted from FrogUI verified that roms/nes/audit.nes defaults to /mnt/sdcard/cubegm/cores/quicknes_libretro.so. The accepted /mnt/sdcard/roms/FC/r36sx_achievement_lab.nes defaults to /mnt/sdcard/cubegm/cores/fceumm_libretro.so. The two paths are platform aliases but select different default cores.
4. An existing per-ROM override can choose FCEUmm for precisely /mnt/sdcard/roms/nes/audit.nes. Host evaluation of the same C path proved it wins over a folder override and leaves another NES game on QuickNES. Use the existing FrogUI override mechanism for the selected test ROM, confirming the exact installed core SHA-256 c318c4217bf8c0396161e9a896289d85aa92219e5ef6abf44e89161c2e4954d8. No change to ordinary NES defaults, no duplicate core-selector field on SD and no implicit override inferred from definitions.
5. FrogUI launch passes the resolved core path and ROM path through the existing launch request and shutdown; PicoArch opens them in the gameplay process. The installed FCEUmm uses a full path. Its effective content must be hashed from the same loader-controlled final path the core opens, including patch/extraction materialization when supported. The provider exposes 2 KiB of system RAM for the approved core. Generalized readiness remains disabled if actual core, verified bytes, provider or capability differ. The runtime must not silently fall back to QuickNES for evaluation.
6. The original FC route was physically accepted with the original ROM and tested FCEUmm 10/10. The Studio nes route and override precedence were checked in host without booting a device or writing launch requests to disk. Physical verification of a generalized export and runtime remains pending.

## Joint handoff rule and version decision

Use lowercase logical keys in new v1 identity JSON and exact ROM locators. Public producers emit the final physical folder token for new RA-02.1 records and preserve unrelated legacy records. Public consumers recognize unique legacy logical and folder aliases, verify the exact selected path and console binding, and reject unsafe ambiguity. Fields and storage shape are unchanged. Remain on contract major 1 with a new pinned Git revision. Identity hashes, condition strings, progress scopes and official IDs are unchanged. No automatic SD rewrite is required.
