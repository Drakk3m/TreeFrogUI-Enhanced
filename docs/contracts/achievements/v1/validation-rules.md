# Validation and resource limits

Schema validation is necessary but not sufficient. A reader validates UTF-8, kind/version, shape, semantic identities and resource policies independently. Use strict duplicate-key detection, integer parsing with checked ranges, normalized relative paths and checked multiplication/addition before allocating. Open relative to verified SD root with no symlink traversal or nonregular files. Reject absolute, backslash, drive, traversal, dot/empty and Windows-reserved components, case-fold collisions on FAT, and overlong byte strings. Never accept a metadata filename as a filesystem path or executable source. Validate all result bytes while streaming before a record becomes authoritative. Files that exceed limits fail locally and ordinary gameplay/discovery remains available.

| Limit | Proposed v1, unless identified as observed |
| --- | --- |
| Generalized JSON document | 192 KiB encoded, nesting depth ≤10, strict scalar Unicode strings |
| Relative paths | 512 UTF-8 bytes, each component ≤255 bytes |
| Definition and snapshot rows | 128 per scope/definition, up to two complete progress slots |
| Conditions | 1,024 ASCII bytes; ≤32 terms, max 9,999 hits per term. Admission subset for NES provider below. |
| rcheevos parsed budget | 4 KiB per trigger and 128 KiB per set in host size preflight. Target must independently enforce allocation, arithmetic and peak budget before activating. |
| Target parser and compositor | Provisional 384 KiB parser+metadata preparation budget, decoded icons only as needed and bounded queue of six notifications. Existing RGB565 buffers. No additional full panel buffer. |
| Identity and a set's components | First raw verifier streams in ≤64 KiB chunks and accepts ≤256 MiB per effective ROM. Fileset ≤32 components, checked aggregate ≤256 MiB before first implementation approval. |
| Assets | 128 KiB compressed PNG; badge ≤64×64, avatar ≤96×96; 8-bit RGB/RGBA, non-interlaced. Only IHDR, IDAT, IEND in order with validated CRC and small decoded output; no external resources. |
| Proven observed legacy behavior | Device FCEUmm region 0–2047, exact original NROM ROM, six triggers, six queue slots and legacy two-digit mask. Original laboratory physically verified. |

NES direct-byte capability v1 admits a deliberately restricted subset of existing rcheevos syntax. A condition is at most 32 underscore-separated terms; each has optional M: or R:, a byte address 0xH followed by 1–8 hex digits (optional d prefix), one comparison (=, !=, <, <=, >, >=), another byte operand or decimal literal 0–255, and optional .N. positive hit target up to 9,999. Each use must declare byte/delta/hitcount/measured/reset-if as applicable. Provider ranges must contain every accessed byte, be nonoverlapping and end at or before 2^32. Reject indirect addresses, pointer arithmetic, write access, alternate sets and undeclared operations for this provider. This is an admission filter, not an expression evaluator. Then parse each exact string with pinned rcheevos; preflight per-trigger and aggregate budgets before activation. On-device validation uses its own compiled provider registry, regardless of what an SD capability file declares. No authorization is granted by the fixture directory.

The host tools deliberately validate self-contained raw unarchived packages strictly, including the referenced ROM/definition for all scopes and required assets. Their SHA/content check runs on the reference SD only. A production recovery importer may retain a structurally intact missing-association record in quarantine without trusting or counting it. The host tool does not emulate gameplay, test FAT crash behavior, validate a fileset adapter, or qualify a new core. The initial generalized producer must measure parser peak and evaluation at target, including worst-case valid input and malicious malformed inputs, prior to physical acceptance.

Identity semantic gate: resolve the locator in the correct role (CubeGM first-level folder or TreeFrogUI roms/<folder>); independently normalize platform, reject unqualified aliases and require a unique canonical match and the registered RA console ID before interpreting an RA association. Generalized v1 requires the canonical lowercase key even when multiple physical folders are accepted. Legacy public values may be uppercase Studio tokens or recognized folder aliases. Neither check relaxes the effective ROM SHA-256 gate.
